IMPORTANT TOOLING CORRECTION (found this round): plain `npx tsc --noEmit` in
`Client/` is a SILENT NO-OP - the root `tsconfig.json` has `"files": []` and
only project references, so it type-checks nothing and always exits 0. Every
prior round's "typechecks cleanly via tsc --noEmit" claim was therefore
unverified. The correct command is `npx tsc --noEmit -p tsconfig.app.json`.
Re-running that now shows the same ~14 pre-existing errors already known
about from `npm run build`/`tsc -b` (primaryTypographyProps/InputProps/
PaperProps, one Stack `alignItems`-as-direct-prop case in
WorldSettingsPage.tsx) and nothing new - so the prior rounds' work happens
to still be clean, but that was luck, not verification. Use `-p
tsconfig.app.json` (or `tsc -b`) from now on. Also confirmed this round: MUI
v9 in this install throws a TS2769 overload error when `alignItems`/
`justifyContent` are passed as direct props on `<Stack>` - it only works
inside `sx={{ alignItems: '...' }}`. This is the root cause of most of the
~14 pre-existing errors and is worth fixing opportunistically when touching
those files, but wasn't blanket-fixed this round (out of scope).

WHAT'S LEFT / KNOWN GAPS FROM THIS ROUND
-------------------------------------------
[ ] Not click-tested in an actual browser - see the tooling note above; this
    is doubly worth doing now that we know `tsc --noEmit` alone wasn't
    actually gating anything in prior rounds either.
[ ] The ~14 pre-existing MUI v9 typing errors (see tooling note) are
    unrelated to this round and were left alone - worth a dedicated cleanup
    pass (mostly mechanical: move `alignItems`/`justifyContent` into `sx`,
    swap `primaryTypographyProps`/`InputProps`/`PaperProps` for the MUI v9
    `slotProps` equivalents) before trusting `npm run build` as a gate.
[ ] Widget layout editing (issue 7g) is intentionally non-functional - the
    edit pencil is a static placeholder, per the issue's own "not a
    necessity to make it working."
[ ] Docker Hub/GitHub widgets depend on the browser being able to reach
    those public APIs directly (no backend proxy) - both degrade to a small
    "unavailable" state on fetch failure, but haven't been tested against
    real network conditions like CORS/rate-limiting in a deployed
    environment, only local dev.
[ ] Linked articles (issue 4a/4c/4f/4g/4h) use a loose `linked_entity_type`/
    `linked_entity_id` reference (no FK, no cascade-delete) - deleting the
    "real" NPC/Creature/Spell/Item an article is linked to does NOT delete
    or unlink the article; it just becomes a dangling reference. Worth
    deciding on cleanup behavior later if this becomes a real pain point.
[ ] Right panel utility strip's TODO/Notes (issue 8a) are per-world
    localStorage scratch state (`useQuickToolsStore`), not synced to any
    backend or shared across devices/players - same reasoning as other
    prototype-tier features in this codebase (random encounter tables,
    Manage Tokens UI memory).
