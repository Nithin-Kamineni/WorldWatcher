WorldWatcher - Feature Progress
=========================================
Last updated: 2026-08-16

Covers three earlier rounds (see below, unchanged) plus this round: a large
batch across Campaigns, Factions, DM Panel/NPCs, Map bug fixes, and an NPC
randomizer. Check marks in the three earlier sections mean "verified
in-browser" (Playwright smoke tests). This round's checkmarks mean
"typechecks cleanly (tsc + vite build) and confirmed live against the
running backend via curl (migrations applied, endpoints return the new
fields)" - there is no browser-automation tool in this environment, so
nothing below was click-tested in an actual browser session; that's still
worth doing before calling this round done.

ROUND 4 (2026-08-16): CAMPAIGNS, FACTIONS, DM PANEL/NPCs, MAP FIXES, NPC RANDOMIZER
-------------------------------------------
[x] Campaigns page: card corner radius reduced (was accidentally 56px via
    the global theme multiplier); hover tooltip shows name/ruleset/
    description (backend already had these fields, frontend just wasn't
    reading them)
[x] Factions: relations (Faction A <-> Faction B) now editable directly
    from the faction form dialog (edit mode only - a brand-new faction has
    no id yet to attach a relation to) and therefore from the table view
    too, not just the diplomacy graph; added a `strength`-tiering
    `importance` field (primary/secondary) per relation and an `influence`
    field per faction (petty/local/minor/regional/major) - both new DB
    columns, migrated and backfilled for the existing 8-faction/11-relation
    sample data in both seeded campaigns
[x] Factions bug fix: the diplomacy graph's ring used to show every
    faction regardless of whether it actually had a relation to the
    center - now filtered to only related factions
[x] Factions graph: node size scales by influence (local/minor/regional/
    major -> 44/54/64/80px), petty factions never appear in the graph at
    all; new influence filter chip group (graph view's search/filter bar)
    hides tiers other than the center's; radial position now depends on
    relation importance (primary = inner dashed ring - previously drawn
    but unused, secondary = outer ring); edge stroke width now tiers by
    importance (primary 3-5px, secondary 1-2px) with strength still
    varying weight inside the tier; canvas bumped 560->680px with a wider
    outer ring to fit the two-ring layout comfortably
[x] Factions overlay: legend moved from an always-visible panel to a small
    (i) icon opening a popover; detail panel's responsive breakpoint
    dropped lg->md so it stays beside the graph at more screen widths; the
    low-contrast "selected faction" comparison bar recolored
    secondary->info (better contrast in both themes, no global theme
    change); Add/Edit/Delete toolbar collapses behind a toggle button
[x] DM Panel: NPCs split out of the old 4-way "Creatures" hub into their
    own top-level tab; the hub (now Monsters/Spells/Magic Items only) is
    renamed "Compendium". NPCs and Monsters still share one `creatures` DB
    table (avoids duplicating the whole stat-block schema) via two new
    columns: `base_creature_id` (which monster, if any, an NPC's stats
    were autofilled from) and `is_custom_build`
[x] NPC form: Custom/Creature toggle - Creature mode searches the monster
    catalog, autofills the whole stat block (still editable after) and the
    portrait (unless you've already uploaded your own this session);
    Custom mode is the old manual-entry behavior. New free-text
    Description field (separate from the existing narrative History field)
[x] Map bug fix: sidebar Favorites star not updating until refresh - root
    cause was TokenLibraryPanel's paginated-list merge only appending
    unseen ids and silently dropping in-place updates (like a favorite
    toggle) to anything already loaded from an earlier page
[x] Map bug fix: opening the "Random Encounter" table dropdown inside
    Manage Tokens -> Encounters closed the whole popover - classic MUI
    nested-portal ClickAwayListener issue, fixed with disablePortal on
    that dropdown's menu
[x] Map: Manage Tokens now remembers which tab (This Floor/Favorites/
    Encounters) you were last on, and which random-encounter table was
    selected, across popover close/reopen and page reload (new
    localStorage-only UI-state store - deliberately not a DB table, same
    reasoning as the original random-encounter-tables prototype)
[x] Map: Reset View now actually computes a fit-to-viewport scale (reading
    the live, fullscreen-aware Stage size) and auto-picks whichever of the
    4 rotations best fills the screen without stretching, persisting that
    rotation like a manual Rotate click would - previously it just reset
    zoom/pan to 1:1 regardless of screen size or aspect ratio
[x] NPC randomizer: die icon next to "Add NPC" randomizes every unlocked
    field on a fresh NPC; every randomizable field (name, relation,
    importance, profession, motivations, pitfalls, Custom/Creature toggle)
    has its own lock + dice pair - locking protects a field from both its
    own dice and the "randomize all" button. Names come from 4 new
    `random_*` reference tables seeded once from 5etools' names.json
    (2,723 first/last names imported, everything else in that file
    discarded) plus hand-authored profession/motivation/pitfall lists
    (36/5/5 entries - flagged as a first draft worth a content-review pass)

DRAWING TOOLS, GRID, FLIP, ROTATE
-------------------------------------------
[x] AoE/drawing tools: circle, cone, square, rectangle, line, thin line
    (fixed 3px), freehand marker (adjustable color + thickness), all
    erasable
[x] Ruler tool: temporary dashed line + live "N.N (N.N feet)" label,
    disappears on mouseup, never persisted
[x] Grid style popover: color, thickness, square-vs-hex type, per map
[x] Map flip (horizontal + vertical) and 90-degree rotate (cumulative,
    wraps at 360), both per floor
[x] BUG FIX: shapes drawn and tokens dropped on a flipped/rotated floor
    now land exactly under the cursor. Root cause was new points/shapes
    being captured in raw screen space but then rendered a second time
    through the flip/rotate transform (double-applying it). Fixed with an
    explicit visual<->local coordinate conversion applied once, at commit
    time, and by rendering the live draft preview outside the transform
    entirely (same approach the ruler already used) so it always tracks
    the cursor while dragging regardless of flip/rotate state.
[x] Token art stays upright under flip (counter-scaled); tokens
    deliberately rotate *with* the board under rotate (not counter-
    rotated) - these were confirmed as the two different expected
    behaviors (flip must not mirror art; rotate is "spin the board")

    toolbar's Favorites tab, the sidebar Tokens panel, and the Creatures

[x] Placed-token pixel size = current size x the map's grid size, clamped
    to the existing 16-110px range
[x] Initiative bar always uses fixed box sizes regardless of token size,
    as requested

INITIATIVE TRACKING
-------------------------------------------
[x] Sidebar flow: Roll Initiative (d20 + DEX modifier, shown as an
    editable "d20 [_] + N = total" breakdown per creature) -> Start
    Encounter (or Cancel) -> Next Turn / End Encounter
[x] Floating initiative bar over the top of the map: current-turn box
    larger, border color matches the token's outline color, click the
    current box to advance the turn
[x] Rebuilt 3-state collapse: full (horizontally-scrollable row, themed
    thin scrollbar) -> compact (previous/current/next only - 3 boxes if
    there's no "previous" yet, 4 otherwise; current at 50% opacity, the
    others at 80% transparent) -> hidden -> back to full. Collapse button
    is now a fixed element next to the row instead of trailing after
    however many tokens there are.
[x] Bar background is more transparent (25% black, was 50%) so more of
    the map shows through
[x] Combat tracking moved into the Initiative panel itself (no need to
    switch to Manage Tokens while running the encounter): each active
    row expands to show current/max HP, a concentration checkbox,
    death-save pips (once HP <= 0), and a freeform notes field for spell
    slots/abilities/anything else

DICE ROLLER
-------------------------------------------
[x] Toolbar icon opens a popover: pick a die (d4-d20), pick a count,
    "Roll" triggers a ~0.7s animated number-cycle before settling on the
    real result; shows each die plus the total. Fully ephemeral, nothing
    persisted.

KNOWN SIMPLIFICATIONS / NOT DONE
-------------------------------------------
[ ] Map flip/rotate pivot around the *stage* center, not the exact
    background image center - visually identical whenever the image is
    centered in the stage (the normal case)
[ ] Hex/square grids are purely visual - no snapping for tokens or shapes
[ ] Hobgoblin, Merfolk, and Pixie still have no real token art (fallback
    initial-letter avatar shown instead, on the map, in the initiative
    bar, and in every list)
[ ] Encounter "Challenge Rating" is a freeform text field, not
    auto-computed from the creatures added
[ ] Combat tracking is intentionally lightweight (HP, concentration,
    death saves, freeform notes) - no structured spell-slot/resource
    system, per your "don't bother too much, I'll improve it later" note
[ ] Custom (one-off) encounter creature entries don't have the
    default/current size split - just a flat size, since there's no
    reusable definition to "reset to" for a one-off entry
[ ] Undo/redo covers floor-level edits only (tokens, shapes, flip,
    rotate) - grid settings, initiative/roll state, and encounter lock
    changes are intentionally excluded (not typical "oops" targets, and
    would flood the history stack)
[ ] "Cancel" only exists in the pre-start "rolling" initiative state;
    once active, "End Encounter" is the one-click way to stop it
[ ] Random Encounters is still a visible but disabled placeholder button
[ ] Advanced table search is a shared visual pattern with per-table
    filter logic, not one generic column-introspection engine - adding a
    new filterable column to a table means adding a chip group for it,
    not something that happens automatically
[ ] No automated regression test suite - verified via manual Playwright
    smoke tests during development
[ ] Touch/mobile input hasn't been tested for any of the newer
    interactions (drag-and-drop, drawing tools, dice roller)
[ ] Round 4 (Campaigns/Factions/NPCs/Map fixes/randomizer) was verified by
    typecheck + production build + curling the running backend, NOT by
    actually clicking through the app in a browser - no browser-automation
    tool is available in this environment. Worth an in-browser pass before
    trusting it fully, especially the Manage Tokens popover fix (E2), the
    Reset View auto-rotation (E4), and the NPC creature-picker autofill.
[ ] random_professions/random_motivations/random_pitfalls are a
    hand-authored first draft (36/5/5 entries) seeded once from the
    importer script, not reviewed for tone/setting fit - worth a look
    before relying on the randomizer for real sessions
[ ] NPC importance randomizer picks among all existing importance values
    except 'monster' (boss/npc/side-character/recurring/important/
    quest-giver/minion/summon) - not narrowed further; flag if that's not
    what you had in mind for "NPC importance"
